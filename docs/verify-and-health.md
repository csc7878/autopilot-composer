# 结果校验（Verify）与元素库健康度指南（v3.4.1）

> 对应引擎版本 v3.4.1。本文讲两个可靠性机制：**步骤级结果校验**（判断动作是否真的生效）
> 与**元素库健康度自愈**（脆弱定位器自动遗忘、元素自动复活）。
> 小白入门看《小白使用说明.md》第 8 节；T1 直连层看 `docs/t1-direct-layer.md`。

---

## 1. 为什么需要结果校验

确定性回放长期存在一个断层：**"点击成功"不等于"操作生效"**。

典型翻车场景：

| 场景 | 现象 | 旧版行为 | v3.4.1 行为 |
|---|---|---|---|
| 表单校验未过 | 按钮点了但弹出"用户名不能为空" | 记成功，继续跑，后面步骤全乱 | 该步校验不过 → 重试 → 停在断点 |
| 后端拒绝 | 接口返回 200 但业务码是"失败" | 记成功，数据没入库没人知道 | 校验不过 → 降级走界面重新提交 |
| 导出慢 | 点了导出，文件 3 秒后才生成 | 下一步因文件不存在而报错 | 轮询等到文件出现再继续 |
| 加载遮罩 | 点了保存，页面还在转圈 | 直接执行下一步，点到遮罩上 | 校验遮罩消失才继续 |
| 页面跳转慢 | 点了登录，还没跳转 | 下一步在旧页面找元素 → NOT_FOUND | 轮询等 URL 变化后再继续 |

一句话：**把"我以为成功了"变成"我验证过成功了"**。

## 2. 快速上手：给关键步骤加一行校验

在 `task_flow.json` 的步骤里加 `verify` 字段即可（单个对象或数组，数组需全部通过）：

```json
{
  "type": "browser",
  "func": "click_elem",
  "args": ["#btn-save"],
  "comment": "点击【保存】  〔校验：页面含「保存成功」〕",
  "verify": [
    { "type": "text_present",   "text": "保存成功" },
    { "type": "element_absent", "selector": ".loading-mask" }
  ]
}
```

跑 `python main_task.py` 时，通过会多打印一行：

```
  ✅ 步骤 1/4  [点击【保存】] {T2(cdp)}
     ✔ 结果校验通过
```

不通过则该步按失败处理（重试 → 降级 → 断点暂停），并打印具体原因：

```
  ⚠️ 步骤 1/4  [点击【保存】] {T2(cdp)} 重试 1/3：结果校验未通过：页面应包含文本「保存成功」（未命中）
```

> **不必给每一步都加校验**。只加在「有明确成功信号」的关键步骤（保存、提交、登录、导出、删除）上，
> 性价比最高。给每步都加反而会让流程更脆弱。

## 3. 校验类型参考（11 种）

| type | 必填字段 | 判定 | 典型用途 |
|------|----------|------|----------|
| `element_exists` | `selector` | 元素出现（个数 > 0） | 结果列表出现、弹窗打开 |
| `element_absent` | `selector` | 元素消失 | 加载遮罩消失、弹窗关闭 |
| `element_count` | `selector` + `count` | 个数等于指定值 | 列表恰好 3 行 |
| `text_present` | `text` | 页面可见文本包含 | "保存成功"、"提交成功" |
| `text_absent` | `text` | 页面可见文本不包含 | 不应出现"错误"/"失败" |
| `url_contains` | `value` | 当前 URL 包含子串 | 登录后进入 /dashboard |
| `url_equals` | `value` | 当前 URL 相等（忽略尾部 /） | 精确落到某页 |
| `element_value_equals` | `selector` + `value` | 元素 value/innerText 相等 | 合计金额 = 1000 |
| `element_value_contains` | `selector` + `value` | 元素值包含 | 单号含 "SO-" |
| `window_title` | `value` | 前台窗口标题包含（桌面） | Excel 打开了某文件 |
| `file_exists` | `path` | 文件已生成 | 导出/下载完成 |

两个通用可选字段：

- `timeout`：该条校验的轮询上限秒数（默认取 `config.json` 的 `verify_timeout` = 5 秒）。慢系统可写大一些，例如 `{"type":"file_exists","path":"./out.xlsx","timeout":30}`；
- 轮询间隔由 `config.json` 的 `verify_interval`（默认 0.3 秒）统一控制。

**选择器写法**：`selector` 支持 CSS 与 XPath（与元素库一致），例如 `#kw`、`.order-row`、`//button[text()="提交"]`。

**浏览器未连接时**：网页类校验会标记为「跳过」并通过（避免桌面-only 流程被误拦），
跳过项会计入结束时的统计（`结果校验：通过 N 项，跳过 M 项`）。

## 4. 常用配方（可直接复制改选择器）

**① 登录之后**
```json
"verify": [ { "type": "url_contains", "value": "/dashboard" } ]
```

**② 保存/提交之后**
```json
"verify": [
  { "type": "text_present", "text": "保存成功" },
  { "type": "text_absent",  "text": "失败" }
]
```

**③ 导出/下载之后**（等待文件真正生成，最多等 30 秒）
```json
"verify": [ { "type": "file_exists", "path": "./exports/2026-09.xlsx", "timeout": 30 } ]
```

**④ 查询之后**（确认结果行出现）
```json
"verify": [ { "type": "element_exists", "selector": ".result-row" } ]
```

**⑤ 删除之后**（确认该行真的没了）
```json
"verify": [ { "type": "element_absent", "selector": "tr[data-id='1001']" } ]
```

**⑥ 点击后等加载遮罩消失**
```json
"verify": [ { "type": "element_absent", "selector": ".loading-mask", "timeout": 15 } ]
```

**⑦ 金额/数量核对**
```json
"verify": [ { "type": "element_value_equals", "selector": "#total", "value": "1000.00" } ]
```

**⑧ 桌面软件操作后**（前台窗口标题变化）
```json
"verify": [ { "type": "window_title", "value": "月度报表.xlsx" } ]
```

**⑨ T1 直连步骤**：API 步骤建议用模板自带的 `assertions`（见 `docs/t1-direct-layer.md` §4.3），
也可叠加 `verify` 做业务级校验：
```json
{
  "type": "api", "func": "call_api", "args": ["POST_submit_order"],
  "credential_ref": "erp_token",
  "verify": [ { "type": "element_exists", "selector": "#order-list tr:first-child" } ]
}
```
（T1 成功但界面没刷新 → 自动降级走界面路径，两条路径都校验，这是 v3.4.1 新增的行为。）

## 5. 校验失败怎么排查

第一步看控制台/`run_log.log` 里的失败详情，它直接写明**期望与实际**：

```
结果校验未通过：页面应包含文本「保存成功」（未命中）
结果校验未通过：元素应消失 '.loading-mask'（实际 1 个）
结果校验未通过：文件应已生成 ./exports/a.xlsx
```

判断分两类：

| 详情特征 | 性质 | 处理 |
|---|---|---|
| `元素应出现 '#x'（实际 0 个）` 且该步有 `element_ref` | **定位器问题**（元素改了/还没渲染） | 用 Chrome 检查更新元素库选择器；或加大 `timeout` |
| `页面应包含文本「…」（未命中）` 但元素确实点到了 | **流程问题**（业务被拒/前置条件不满足） | 看页面报错文案，补上前置步骤 |
| `文件应已生成 …` 一直不过 | 导出动作本身没触发或路径不对 | 确认导出按钮点对了、`path` 与实际落盘路径一致 |

设计上已经把两类问题**自动关联**起来：校验失败时，若该步用了元素库定位，
会记一次 miss（`miss_streak +1`），所以**反复因定位器失效而校验失败的元素会自己浮到 `--health` 报告里**。

## 6. 元素库健康度与自动遗忘

### 6.1 机制

回放时每个定位器的命中/未命中都会记账：

| 层级 | 计数 | 自动遗忘阈值 | 遗忘后的行为 |
|---|---|---|---|
| **定位器级** | `hit` / `miss` / `miss_streak` | 连续 5 次未命中（`locator_stale_threshold`） | 后续回放**跳过该策略**，让位于更可靠的策略 |
| **元素级** | `hit_count` / `miss_streak` / `last_ok_ts` | 连续 15 次未命中（`stale_threshold`） | 标记 `stale` **待人工复核**（不删除），回放时打印警告 |

三条关键规则：

1. **任一命中即复活**：`miss_streak` 归零、`stale` 清除 —— 界面改版后又改回来，元素能自动恢复，不需要人工干预；
2. **全部遗忘时兜底**：某元素所有策略都被遗忘时，回放会退回原顺序再试一遍 —— 「有线索总比直接失败好」；
3. **只降权不删除**：自动删除会丢掉唯一的定位线索，标记 `stale` 既能让回放避开，又保留复核与恢复的可能。

### 6.2 查看与恢复

```bash
python main_task.py --health          # 体检报告
python main_task.py --health-reset    # 人工复核后：恢复被自动遗忘的元素（miss_streak 归零）
```

报告示例：

```
元素库健康度：共 46 个元素，45 个正常，1 个待复核
（其中 40 个尚未回放过，不计入问题元素）
定位器自动遗忘：2 个元素有策略被跳过

最需要关注的元素（按连续未命中排序）：
  - 按钮_保存（erp.internal）命中 3 次、连续未命中 16 次，定位器 2 个，已跳过策略：css
```

**怎么读**：
- `尚未回放过` 是**正常状态**，不是问题（新录的元素还没跑过）；
- `连续未命中` 高的元素 = 界面真的改了，需要去更新它的定位器；
- `已跳过策略` 说明某个脆弱选择器（常见是 `css` 链式路径）被自动淘汰了，元素仍在靠其它策略工作。

### 6.3 数据落盘

- 统计写在 `elements.json`（`version: 2` + `meta.stale_threshold` / `locator_stale_threshold`）；
- 落盘时机：每 20 步一次 + 全部完成 + 失败暂停时，**不含预置元素库条目**（不会把预置库固化进用户库）；
- 旧版 `elements.json`（无健康字段）会自动补齐，**向后兼容**。

## 7. 设计取舍（为什么这么做）

| 决策 | 原因 |
|---|---|
| 不引入 VLM / Grounding 模型（如 ZonUI-3B）替代定位器 | 小模型在专业高分辨率桌面基准 ScreenSpot-Pro 上仅约 28%，且本类用户多为低配 Windows（无独显、32 位 Python），本地跑 3B 模型物理不可行、且会把安装门槛从「pip install」变成「装 CUDA」 |
| 不引入 Node 生态 Agent 框架作为执行引擎 | 会作废已建成的 T1 直连层 + 凭证隔离 + 审计日志，且从「确定性可复现」变成「每次跑法可能不同」，与企业审计要求冲突 |
| `verify` 需手写而非全自动生成 | 自动生成的「成功信号」不可靠（点了按钮元素当然还在），会给用户虚假的安全感 |
| 遗忘只降权不删除 | 保留唯一线索，可复核可恢复 |
| 无 `verify` 字段的流程行为完全不变 | 新机制绝不能误拦正常流程（A14/D4 已用断言固化） |
| 校验失败同时计入元素库 miss | 让「定位器选错」变成可归因数据，而不是靠人回忆 |

## 8. 已知边界与后续可做

- **未做**：录制时自动生成 `verify` 候选。可行方向是录制中对比「点击前后 DOM 差异 / URL 变化」，
  生成**候选**规格让人确认（而非直接写入），避免虚假成功信号；
- **未做**：`verify` 的 `retry` 独立配置（目前跟随该步的 `max_retry`）；
- **未做**：桌面 UIA 元素级的健康度记账（目前健康度覆盖网页定位器；桌面坐标步骤无定位器可记）。
